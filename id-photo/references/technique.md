## 一、规格与底色标准值

### 蓝色（最容易搞错）

| 用途 | RGB | 亮度 | 出处 |
|---|---|---|---|
| 一寸蓝底官方标准 | (67, 142, 219) | 143 | 一寸蓝底制式规范 |
| 学籍系统常用淡蓝 | (100, 197, 255) | 184 | 2026 学籍照要求 |
| 山东学籍淡蓝 | (180, 220, 240) | 213 | 山东省教育厅 |
| 学历/职场通用浅蓝 | (0, 191, 243) | 145 | 通用参考 |

**坑**：曾误用 (67,142,185)，B 值少 34，视觉上明显发灰发暗，用户一眼看出。**蓝色底必须用 219 或以上。**

## 二、构图标准

### 头高占比

- 标准区间 **60%~70%**，默认取 **0.65**
- 头高 = 头顶到下巴的距离
- 画面高度 = 头高 / head_ratio
- 头太小（<55%）显得人远，头太大（>75%）像"大头贴"且头顶顶边

### 头顶留白

- 标准区间 **8%~12%**，默认取 **0.085**
- 留白 = 画面高度 × top_space
- 儿童脸相对偏大，取区间下沿更合适

### 水平对齐

以**脸部最宽处（颧骨/耳朵）**的水平中线对齐画面中心，不是头顶或下巴的中线。

### 常见错误对照

| 现象 | 原因 |
|---|---|
| 脸占满画面、头顶顶边、下巴贴底、肩不可见 | 裁切框太小，head_ratio 过高 |
| 头太小、像半身照、画面一半是衣服 | 裁切框太大，head_ratio 过低 |
| 人像偏左或偏右 | 水平基准取错（应用颧骨行中线） |
| 无肩部 | 画面高度不足，或 top_space 过大挤压下方 |

## 三、抠图（u2net）

### 模型

- 文件：`u2net.onnx`，176MB
- 位置：`~/.workbuddy/models/u2net.onnx`（共享，多 skill 复用）
- 输入：`input.1`，形状 `[1, 3, 320, 320]`
- 输出：`1959`，形状 `[1, 1, 320, 320]`

### 预处理（严格按此顺序）

```python
x = image.resize((320, 320)) / 255.0
x = (x - [0.485, 0.456, 0.406]) / [0.229, 0.224, 0.225]
x = x.transpose(2, 0, 1)[None, ...]        # HWC -> NCHW
```

输出掩码需 min-max 归一化后放大回原图尺寸，填进 alpha 通道。

### 下载源（关键）

GitHub release 在国内**经常断连或返回不完整文件**（实测下到 26.9MB 就断，加载报 `INVALID_PROTOBUF`）。可用源：

1. `https://hf-mirror.com/tomjackson2023/rembg/resolve/main/u2net.onnx` ← **实测可用，176MB 完整**
2. `https://huggingface.co/tomjackson2023/rembg/resolve/main/u2net.onnx`（国内常超时）

**必须校验文件大小 ≥150MB**，小于此值一定是坏的。

### 不需要 rembg 包

直接用 onnxruntime 加载即可，省掉 rembg 的一大堆依赖。实测 `pip install rembg` 在慢镜像上会卡 16 分钟以上。

## 四、去白边 / 去灰边

### 问题成因

u2net 的 alpha 边缘有半透明过渡带。实测**边缘带内 23~29% 的像素颜色仍接近原背景色**（灰白墙 RGB≈178,176,174）。这些像素被当作"半透明人像"合成后，就是可见的灰白描边。

### 算法

```
sim = exp(-(dist_to_src_bg / sigma)^2)      # 1=就是背景, 0=差很远
alpha[edge] *= (1 - sim * strength)          # 越像背景压得越狠
alpha = clip((alpha - lo_cut) / (hi_cut - lo_cut), 0, 1)   # 对比拉伸
```

### 参数方向（反直觉，重要）

**`sigma` 越大，压制范围越广（越激进）。** 实测：

| sigma | 白边残留像素 |
|---|---|
| 22（看似激进，实际范围窄） | 7237 |
| 40 | 1980 |
| **60** | **83** ← 最优 |
| 80 | 44 |

最优：**sigma=60, strength=0.90**，残留从 23013 降到 83（大图），缩到 236×315 后为 **0**。

### 必须验证人像没被抠洞

激进压制可能误伤脸的高光、浅色衣服。验证方法：用 `MinFilter` 腐蚀 25 次取人像深部，检查 alpha<0.9 的破洞数。

实测 sigma=60 时破洞 **0**，深部最小 alpha 1.00。

### 验证成品白边

四角 12×12 块与标准色比对：
- 顶部两角应为纯背景，偏差 ≤3（JPEG 量化误差）
- **底部两角会因人像肩膀入镜而偏离**——这是规范要求的"肩部完整入镜"，不是污染

另查：`(dist_to_bg > 18) & (dist_to_bg < 60) & (R > B)` 的像素数（偏暖偏白且非人像），应为 0。

### 补充：两种"灰边"必须分清（2026-09 实测）

去污染公式 `true_fg = (fg - (1-a)*src_bg) / a` 假设的是 **alpha 混合**
（半透明前景叠在背景上）。但有两类边缘像素不符合这个假设：

| 类型 | 典型色 | 特征 | 成因 | 对不对症 |
|---|---|---|---|---|
| **中性灰边** | `(149,140,137)` R≈G≈B | 深色短发 + 亮背景 | 发丝与背景**空间交替**（碎发缝隙透光） | **不对症**，需 `transition_kill` |
| **暖棕雾带** | `(136,111,94)` R>G>B | 蓬松长发 | 光穿透细发，发丝半透明 | **不对症**，无解 |

**判据：算 R-B。** > 20 → 暖棕（无解）；≈0 → 中性灰（可修）。

#### 中性灰边：`transition_kill`

空间混合像素的颜色 = 黑发丝 × 覆盖率 + 亮背景 × (1-覆盖率)，
去污染公式会把它反推成一个"中亮暖灰"第三色 `(126,130,128)`，合成后
比底色亮 48 个点 → 视觉上"发亮"。

对策：过渡带内 `lum > transition_kill` 的像素**直接判为背景**（alpha→0），
不做混合。默认 60。受控实测（含 refine_alpha 的完整流程）：

| transition_kill | 发丛内灰 | 人像保留 |
|---|---|---|
| 0 | 832 | 100% |
| 60 | 611 | 98.7% |
| 110 | 733 | 98.8% |
| 150 | 832 | 98.8% |

**收益在 ≤70 饱和；阈值调高反而变差**（refine_alpha 已把过渡像素压暗，
阈值太高会漏掉它们）。

**⚠️ 调参必须在完整流程里做。** 早期在不含 `refine_alpha` 的脚本里测出
"最优 110、收益 35%"，走完整流程后只剩 -27%、最优值也变成 60 —— 因为
`refine_alpha` 和本参数在做同一件事（都把 alpha 中间态往两端推），
先跑 refine_alpha 会把可处理的像素吃掉一大半（4.20% → 2.06%）。

#### 暖棕雾带：确实无解

见第十四节的「修正」小节，四版判据已全部实测失败。

## 五、肤色检测与美白

### YCbCr 基础判据

```
Y  = 0.299R + 0.587G + 0.114B
Cb = -0.168736R - 0.331264G + 0.5B + 128
Cr = 0.5R - 0.418688G - 0.081312B + 128

肤色: Cb∈[77,130] 且 Cr∈[133,175] 且 Y≥40
```

### 致命误判：粉色衣服

**只用 YCbCr 会把粉色衣服整片识别成皮肤。** 实测误判导致"肤色"占人像 **71.8%**，且分布延伸到图片底部（原始数据里粉色和肤色在 YCbCr 空间几乎重合）。

### 解法：加 `G >= B` 约束

| 物体 | 实测 RGB | 特征 |
|---|---|---|
| 真实肤色 | R137 G93 B73 | **R>G>B** |
| 粉色衣物 | R176 G81 B115 | **B>G** |

加上 `G >= B` 后：粉衣 **100% 排除**，脸部 **100% 覆盖**。

**这条对任何"红色/粉色衣物 + 黄种人肤色"的抠图场景都适用。**

### 美白强度对照片亮度

以实测（人像原始亮度 88.4，已完成整体 gamma 0.68 提亮）为基准：

| 肤色 gamma | 肤色亮度 | 相对提升 |
|---|---|---|
| 1.00（不提亮） | 135.7 | — |
| 0.94 | 140.8 | +5.0 |
| 0.90 | 144.2 | +8.5 |
| **0.86** | **147.8** | **+12.0** ← 推荐 |
| 0.82 | 151.4 | +15.7 |
| 0.76 | 157.1 | +21.4 |

**风险线：肤色亮度不要超过 152。** 学籍系统有人脸比对，审核红线含「重度美颜/滤镜 → 人像比对<60% → 注册失败」。

正常儿童肤色亮度区间：**145~155**。

### 实现两个必守点

1. **mask 必须羽化**（GaussianBlur 10px 左右），否则提亮区与未提亮区之间出现硬边界色块。
2. **羽化后必须再乘一次 alpha**：`w = w * alpha`。否则 mask 溢出人像轮廓，把纯色背景染脏。

## 六、下巴自动定位（最难的一步）

### 为什么不能靠阈值

逐行统计 alpha 掩码宽度，从上到下的典型曲线（实测归一化值）：

```
y=0.288  宽848  (91.7% of max)
y=0.301  宽906  (98.0%)
y=0.314  宽917  (99.3%)  ← 脸最宽（颧骨/耳）
y=0.327  宽881  (95.4%)
y=0.340  宽851  (92.1%)
y=0.353  宽824  (89.1%)
y=0.366  宽786  (85.0%)
y=0.379  宽677  (73.3%)
y=0.392  宽608  (65.8%)
y=0.405  宽571  (61.8%)
y=0.418  宽523  (56.6%)
y=0.431  宽475  (51.4%)
y=0.444  宽453  (49.0%)  ← 脖子最窄（全局极小）
y=0.457  宽449  (48.6%)  ← 全局最小
y=0.470  宽459  (49.7%)
y=0.483  宽518  (56.0%)
y=0.496  宽622  (67.3%)  ← 肩开始
```

**下巴收窄是渐进的**，任何"跌破 X%"的固定阈值都会偏：

| 阈值 | 判定下巴 | 偏离真值(0.440) |
|---|---|---|
| 0.62 | 0.405 | 0.035 |
| 0.70 | 0.383 | 0.057 |
| 0.80 | 0.373 | 0.067 |
| 0.90 | 0.350 | 0.090 |

### 可靠判据：脖子极小点

人的轮廓必然存在"脖子最细处"这个全局极小值（之后因肩膀而骤宽）。

```
下巴 = 脖子极小点 - 1.5% 人高
```

实测标定：

| 偏置 | 判定下巴 | 误差 |
|---|---|---|
| 1.0% | 0.4453 | 0.0053 |
| **1.5%** | **0.4408** | **0.0008** ← 最优 |
| 2.0% | 0.4359 | 0.0041 |
| 3.0% | 0.4268 | 0.0132 |
| 4.0% | 0.4173 | 0.0227 |

还要验证极小点之后宽度确实回升 ≥25%（排除衣物褶皱造成的假极小）。

### 脸最宽处定位

限定在**头顶下方 12%~45% 人高**范围内搜索，避免肩膀干扰。

## 七、提亮分层策略

两层 gamma，作用范围不同：

| 层 | 参数 | 作用对象 | 效果 |
|---|---|---|---|
| 整体 | `--gamma 0.68` | 全部前景（头发/衣服/皮肤） | 人像 88.4 → 119.2 |
| 肤色 | `--skin-gamma 0.86` | 仅肤色区 | 肤色 135.7 → 147.8 |

两者叠加。非肤色区域（头发、衣物）只受整体提亮影响。

**关键：提亮只作用于前景，背景始终保持精确标准色**，否则底色会被染色导致审核不通过。

## 八、体积压缩

### 二分迭代

```
quality 区间 40~96，二分查找 <= max_kb 的最高质量
参数：subsampling=0, optimize=True
```

纯色背景极省体积——236×315 蓝底在 quality=96 时仅 **23KB 左右**，远低于 60KB 限制，余量充足。

### 不同尺寸的合理上限

固定 60KB **只适合小尺寸**。实测二寸(413×579) 用 60KB 会压到贴线（59.3KB，几乎没余量）。

| 像素数 | 建议上限 |
|---|---|
| ≤120K（236×315） | 60KB |
| ≤200K（358×441 / 390×480） | 100KB |
| ≤300K（413×579） | 200KB |
| 更大 | 500KB |

### 透明底 PNG

PNG 无损，600×800 可达 360KB。超限时用 `quantize(colors=256)` 降调色板，逐步减半到符合要求。

## 九、测量口径陷阱

**统计同一指标必须在同一 alpha 掩码口径下比较。**

踩过的坑：v1 用 refine 前的 raw alpha 测人像亮度得 102.6，v2 用 refine 后的得 88.4，两个数字不可比，导致误判"提亮没生效"，白折腾一轮。

**正确做法**：统一用 `core = alpha > 0.99` 取样。

## 十、审核红线（避免退回）

搜索学籍照片规范时确认的红线：

| 红线 | 后果 |
|---|---|
| 穿蓝色/浅蓝衣拍蓝底 | 轮廓融合，AI 判不合格 |
| 头发遮眉 / 不露双耳 | 五官不完整，审核不通过 |
| 重度美颜 / 滤镜 | 人像比对 <60%，注册失败 |
| 用一寸照当学籍照 | 尺寸不符，退回 |
| 文件 >60KB | 平台无法上传 |
| 命名含空格 | 人工退回 |

**交付前主动提醒用户**：衣服是否与背景撞色、是否有严重遮挡。这些是图像处理改不了的，只能重拍。

## 十一、为什么不做成在线网页服务

**需求背景**：曾评估把工具做成"发链接就能用"的网页版。

**结论：纯前端方案不可行。**

| 障碍 | 具体 |
|---|---|
| 模型体积 | u2net 168MB，每个访客首次打开都要下载 |
| 推理算力 | onnxruntime-web 在浏览器内跑，中低端设备单张需 10 秒以上 |
| 移动端 | 手机基本不可用（流量 + 内存） |

**唯一可行路径**：租服务器让模型常驻，前端只传图片。但要承担服务器成本 + 域名 + 备案 + 限流维护。

**不建议做的理由**：
1. 证件照是**低频需求**（人均一年 1~2 次），撑不起服务器成本
2. 市面上免费替代品（微信小程序搜"证件照"）已经饱和
3. 若目的是社群福利，价值在**形象展示**而非工具本身——更省事的做法是直接帮成员处理照片，或写"自拍指南"图文

**若坚持要做网页版**，可行的折中是：单文件 HTML + 本地 Python 后端（需在本机启动服务）。适合自己用，**不适合分发给他人**。

## 十二、底色与尺寸的正交设计

早期版本把"尺寸+底色"绑成预设（`一寸蓝底`/`二寸白底`），导致组合爆炸：4 种尺寸 × 3 种底色 = 12 个预设，而且用户要个"一寸白底"就得问能不能做。

**改为两轴正交**：

```python
SIZES = {"一寸": (236,315), "学籍照": (358,441), ...}
BACKGROUNDS = {"蓝": (67,142,219), "白": (255,255,255), "红": (255,0,0), ...}
```

任意组合，写法 `尺寸+底色`。同时保留组合名兼容层（`_split_combo`），使旧的 `一寸蓝底` 写法仍然可用。

**踩坑**：自定义颜色的 RGB 若用 `,` 分隔（`@67,142,219`），会与"多规格用逗号分隔"的语法冲突。**必须用 `-` 分隔**（`@67-142-219`），并在报错信息里提示用户这一点。
## 十三、全身照：自动检测会失效（实测）

**案例**：一张 3072×4096 的儿童全身照（站立、手插裤兜、背景白墙带踢脚线）。

`find_head_metrics()` **完全失败**：

```
探得: 人高=3503  头顶=592  最宽行=2116  脖子极小=4094(宽191,回升至191)  下巴=1888
实际: 头顶=592  下巴应在 1420 附近
```

- `脖子极小=4094` 已到图片最底部，`回升至 191`（没有回升）
- **算法把"脚"当成了脖子**，下巴因此偏了 0.16

**根本原因**：算法依赖"脖子最细 → 肩膀骤宽"这个特征。全身照里**腿和脚一直延伸到画面边缘**，宽度曲线不存在"肩膀骤宽"的转折点。

**结论**：`find_head_metrics()` 适用于**头肩照或半身照**（人像下方有明确边界）。遇到全身照必须手工标定。

### 全身照的手工标定法

逐行扫描 alpha 掩码宽度，读曲线：

```
y=0.146  宽154    ← 头顶（骤窄）
y=0.232  宽676
y=0.330  宽786    ← 脸最宽（颧骨/耳）
y=0.342  宽777
y=0.354  宽633    ← 下颌骤然收窄！下巴在此
y=0.366  宽760    ← 回升（肩、手臂）
```

**判据**：脸最宽之后，宽度**骤降 15% 以上**的那一行就是下颌。本例 777→633 降了 18.5%。

### 意外发现：手插兜不影响头肩裁切

曾预判"手插兜会导致肩线不自然"，**实测是错的**。手插兜位置在腰部以下，按标准 65% 头高裁切时画面只到胸口，根本看不到手。

**真正影响头肩裁切质量的是发型，不是姿势。**

## 十四、长发/细碎发的蓝晕（重要）

**案例**：齐肩垂发、发丝细碎的儿童照片，蓝底合成后头发外轮廓出现明显蓝色描边。

### 成因（与"背景色残留"是两回事）

米团（短寸头）没有这个问题，妞妞（齐肩碎发）严重。差异在**边缘像素占比**：

| 照片 | 人像边缘带内"像墙色"的占比 |
|---|---|
| 米团（短寸头） | 23~29% |
| 妞妞（齐肩碎发） | **仅 15.3%** |

妞妞那 85% 的边缘像素**不是墙色残留，而是发丝本身的深色半透明边缘**。它们与蓝底 alpha 混合后 → 蓝色光晕。

**结论：背景色相似度抑制（`sim_sigma` / `sim_strength`）对细碎发无效**，因为成因不同。实测把 sigma 从 60 加到 130，残留量纹丝不动（35936 → 35936，已饱和）。

### 反直觉结论：收缩 alpha 会让蓝晕更严重

试过用 `MinFilter` 收缩 alpha 边界（期望削掉外扩的混合区），**结果完全相反**：

| 收缩 | 蓝晕像素 | 主体像素 |
|---|---|---|
| 0px | 1870 | 2506853 |
| 1px | 2482 | 2496834 |
| 2px | 3308 | 2486830 |
| 3px | 4584 | 2476822 |
| 5px | 8853 | 2456897 |
| 8px | 14797 | 2427471 |

**原因**：收缩把 alpha 边界向内推，**暴露了原本被覆盖的深色发丝边缘**，它们与蓝底混合后更蓝。

### 有效方案：不收缩 + 加严对比拉伸

```python
refine_alpha(rgba, src, src_bg,
             sim_sigma=60, sim_strength=0.90,
             lo_cut=0.20, hi_cut=0.80)      # ← 关键：lo_cut 从 0.05 提到 0.20
```

效果：蓝晕 4596 → 1742（降 62%）。**未根治**，放大 3 倍可见，缩到 236×315 后基本不可见。

### 验收标准

量测口径必须限定在**人像边缘带内**（`alpha ∈ [0.35, 0.98]` 且 `B - R > 40`）。
**别用全域统计**——会把整片纯蓝背景算进去（实测误报 1031 万像素）。

### 根本解法是重拍

细碎发 + 深色头发 + 蓝色背景的边缘染色，**是当前抠图技术的边界**。专业照相馆的解法是**绿幕拍摄**，不是后期。

**遇到这类照片，建议用户重拍并把头发扎起来（马尾/盘发）**，这是最有效的一条，能彻底消除问题。

### 修正（重要）：还有一种更常见的"白雾感"，成因完全不同

上一节说的"蓝晕"指**深色发丝与蓝底混合产生的蓝边**。但还存在另一种现象，肉眼上是**灰白色雾带**，成因和治法都不同：

**实测证据**（妞妞成品，放大 10 倍）：

原图头发芯 `(46,39,49)` 深黑，而发丝区域颜色是 `(136,111,94)` ~ `(165,134,108)` —— **R>G>B 的暖棕半透明色**，不是中性灰。

**成因**：光穿透细发，发丝在传感器上呈现半透明的暖棕/浅色。u2net **如实抠出**，合成到蓝底上就是灰白雾。

**关键结论：这不是抠图错误，是原片的光学事实。** 工具没做错任何事。归因别搞错——不是"抠图技术不行"，是**信息在原片里就那样**。

### 已验证失败的修法（勿重复尝试，四种判据全试过）

思路都是"把发丝颜色朝头发芯压暗"。四版实验：

| 版本 | 判据 | 结果 |
|---|---|---|
| v1/v2 | 距离判据：头发芯膨胀 N px 内 | `reach=22` → **脸被染黑**（灾难） |
| v3 | 距离判据收窄 + YCbCr 皮肤排除 | `reach=5` → 够不着发丝，几乎无变化 |
| v4 | 颜色判据：低饱和度中性色 | 圈到的全是背景过渡像素，**一根真发丝都没圈到** |

**v2 失败的量化原因**（值得记住）：皮肤判据写成 `lum > 118` 才判为皮肤，但实测 `alpha>0.9` 的人像像素里 **58.8% 的亮度 ≤118**，全部掉进"发丝"桶被压暗。

**v4 失败的根本原因（决定性）**：

- 真发丝颜色：(136,111,94) ~ (165,134,108)，**暖棕，R>G>B**
- 皮肤颜色：同样暖棕，R>G>B
- 两者在颜色空间**重叠**，且发丝只有 2~4 px 宽（236×315 下）

**在 236×315 分辨率下，暖棕发丝与暖棕皮肤无法线性分离。** 这是方法的原理性天花板，不是参数问题。

### 即使修好也不该修

把暖棕发丝压成深色 = 抹掉照片里仅有的头发层次 → 蓬散发变成"帽子式"实心黑块，**比留着灰白更难看**。

### 补充（2026-09）：中性灰边和暖棕雾带是两回事，别搞混

本节讲的**暖棕雾带**（R-B>20）确实无解。但还有一种**更常见**的边缘缺陷：

- 颜色 `(149,140,137)`，**R≈G≈B 中性灰**
- 出现在**深色短发 + 亮背景**照片的发丛上沿
- 成因是发丝与背景的**空间混合**（不是半透明）

**这一种是可以修的**，用 `--transition-kill`（默认 60）。
详见第四节末尾的「补充：两种"灰边"必须分清」。

**遇到"头发有白边"的反馈，第一步永远是采样像素看 R-B 的差**，
不要凭"看起来像"就归到无解那一类、也不要反过来白费功夫。

### 真正的解法：改拍摄条件

不是"扎头发"（扎了仍有碎发），而是**换光线方向**：

> 让主光源在**正面或侧前方**，头发处于**顺光**状态。

具体操作：白天**面向窗户**拍，别背对窗户。顺光下发丝不透光，灰白雾从源头消失。

**这个问题的本质是拍摄条件，不是后期能力。** 遇到时明确告知用户，别浪费算力调参。

### 验收：多大才看得见

236×315 实际尺寸下，2~4 px 的灰白雾带**肉眼不可辨**。放大 3 倍以上才明显。

**学籍照/报名照的审核不看发丝边缘。** 判断"要不要修"时先用实际尺寸看，别用放大图下结论。

## 十五、背景色估计对"脏背景"的处理

案例中照片四角采样结果：

```
左上 (179,178,177)  右上 (179,179,179)   ← 干净墙面
左下 (173,164,155)  右下 (168,161,151)   ← 踢脚线 + 地板（深棕）
自动估计 → (176,171,165.5)
真实墙色 → (182,181,180)   （图中部两侧）
偏离 19.2
```

**四角采样在有踢脚线/地板/阴影时会失效。** 偏离 19.2 已接近临界，会导致去白边效果打折。

**处理原则**：
- 偏离 <20 可直接用自动估计
- 偏离 ≥20 或肉眼可见四角不一致时，**手工指定背景色**（取图中部两侧的纯净墙面区域）
- 更稳妥的改进方向：采样区块**改为取图中部左右两侧**（避开底部），或对四角做聚类剔除离群块
