# 证件照生成（id-photo）

按用户提供的规格处理普通人像照片。内置尺寸和颜色只是预设，不保证通过接收方审核；交付前需检查实际像素、文件格式、体积和构图。压缩函数会尽力满足体积上限，但极小上限仍可能超限，不得将超限文件标记为合格。

## 什么时候用它

用户给一张人物照片 + 任何"要做成证件照"的诉求：

- "把我家孩子这张照片做成学籍照"
- "照片背景不是蓝色，帮我换一下"
- "这个要求 236×315、蓝底、不超过 60K，能弄吗"
- "一寸照 / 二寸照 / 报名照"
- "背景换成白底 / 红底"

## 怎么用

**第一步：确认参数。** 从用户消息里提取（缺的必须问，别猜）：

| 参数 | 说明 | 常见值 |
|---|---|---|
| 尺寸 | 像素 WxH | 236×315（部分学校）、295×413（标准一寸）、358×441 或 390×480（学籍照）、413×579（二寸） |
| 底色 | 背景颜色 | 蓝色（标准天蓝 / 淡蓝）、白色、红色 |
| 体积上限 | 文件大小 | 学籍照常≤60KB、一寸报名 5~999KB、二寸 ≤500KB |
| 其他 | 特殊要求 | 是否要求肩部完整入镜、是否禁止美颜 |

**第二步：跑引擎。**

```bash
# 在 skill 根目录运行；python 应指向已安装依赖的 Python 3.10+
# 从其他目录调用时，改用此 skill 内 scripts/idphoto.py 的实际绝对路径

# 单规格
python scripts/idphoto.py --src "照片路径" --spec 一寸蓝底 --out "输出路径"

# 多规格一次出全
python scripts/idphoto.py --src "照片路径" --spec "一寸蓝底,学籍照,二寸白底" --outdir "输出目录"

# 自定义尺寸+底色
python scripts/idphoto.py --src "照片路径" --spec "600x800@180-220-240" --out "输出.jpg"

# 透明底
python scripts/idphoto.py --src "照片路径" --spec "600x800" --out "输出.png"

# 看内置规格
python scripts/idphoto.py --list
```

**第三步：自检，必须做。** 跑完使用当前 Agent 可用的图像查看工具检查输出图，肉眼确认：
- 头占画面约 60~70%，头顶有留白，肩部可见
- 底色纯净无杂色、无灰白描边
- 脸没有被美白到失真

发现问题就调参数重跑（见下方参数表），别直接交付。

## 参数速查

| 参数 | 默认 | 什么时候改 |
|---|---|---|
| `--head-ratio` | 0.65 | 头太小改大、头太大改小（范围 0.60~0.70） |
| `--top-space` | 0.085 | 头顶留白太多/太少（范围 0.08~0.12） |
| `--gamma` | 0.68 | 整体太暗调小（0.6 更亮）、太亮调大 |
| `--skin-gamma` | 不启用 | 需美白时传 0.86；觉得不够白给 0.82，别低于 0.78 |
| `--max-kb` | 自动 | 自动值不合要求时显式指定 |
| `--transition-kill` | 60 | **别乱动**。深色短发+亮背景照片的发丛灰边，已调优到 60，见下方专节 |
| `--debug 目录` | 不启用 | 出图不对时保留中间产物排查 |

| 学籍照大 | 390×480 | 部分省份 |
| 护照 | 390×567 | 33×48mm |

### 底色

| 名称 | RGB | 用途 |
|---|---|---|
| 蓝 / 蓝底 | (67,142,219) | 一寸蓝底官方标准天蓝 |
| 淡蓝 / 学籍蓝 | (100,197,255) | 学籍系统常用 |
| 浅蓝 | (180,220,240) | 山东学籍 |
| 深蓝 | (0,90,170) | — |
| 白 / 白底 | 纯白 | 身份证、护照、签证、考试报名 |
| 红 / 红底 | 纯红 | 结婚证、党团、部分档案 |
| 深红 | (200,0,0) | — |
| 灰 / 灰底 | (240,240,240) | 部分签证 |
| 透明 | — | 输出 PNG，后续自己合成 |

### 组合写法（四种，都支持）

```bash
--spec 一寸+蓝              # 显式组合（推荐，语义最清晰）
--spec 一寸蓝底            # 组合名简写，自动拆解
--spec 学籍照+淡蓝
--spec 二寸+白
--spec 一寸                # 只给尺寸，底色默认蓝
--spec 白                  # 只给底色，尺寸默认一寸
--spec 1200x1600@67-142-219   # 自定义尺寸+颜色（RGB 用 - 分隔）
--spec 1200x1600           # 自定义尺寸，透明底
```

多规格批量用逗号分隔：`--spec "一寸+蓝,二寸+白,学籍照+淡蓝"`

**注意**：颜色里的 RGB 必须用 `-` 分隔（`@67-142-219`），不要用逗号——逗号是批量规格的分隔符。

## 交付前必查：着装与背景撞色

**这是图像处理改不了、只能重拍的硬性约束**，交付时必须主动提醒用户：

| 底色 | 不能穿 |
|---|---|
| 蓝底 | 蓝色、浅蓝色、藏蓝色上衣 |
| 白底 | 白色、浅色上衣 |
| 红底 | 红色、粉色、玫红上衣 |

撞色会导致人像轮廓与背景融合，学籍/报名系统的 AI 审核会直接判不合格（"轮廓融合"）。

**实测案例**：粉色 T 恤配红底，视觉上确实有融合感；同一件衣服配白底则更突出。发现用户照片存在撞色风险时，明确说出来，建议换底或换衣重拍，不要默默交付。

**保底建议**：黑色或白色有领上衣，三种底色通吃。

## 关键技术点（改代码前必读）

细节与实测数据见 `references/technique.md`。三条最容易踩的：

1. **蓝色别用错值。** 常用天蓝是 `(67,142,219)`，不是 `(67,142,185)`（差 34 会明显发灰发暗）。学籍淡蓝 `(100,197,255)`，山东学籍淡蓝 `(180,220,240)`。

2. **肤色检测必须加 `G >= B` 约束。** 只用 YCbCr 会把粉色/红色衣服整片识别成皮肤（实测误判率让"肤色"占到人像的 71.8%）。真实肤色恒有 R>G>B，粉衣恒有 B>G。

3. **羽化 mask 后必须再乘一次 alpha。** 否则美白/改色的 mask 会溢出人像轮廓，把纯色背景染脏。

4. **下巴定位靠"脖子极小点"，不靠宽度阈值。** 下巴收窄是渐进的（91→98→99→95→89→85→73→66→62→57→51%），任何固定阈值都会偏。可靠做法是从脸最宽处向下找宽度全局极小（脖子最细处），下巴 = 该点上方 1.5% 人高。实测误差 0.0008。

## 已知限制

处理前先判断照片属于哪一类，这决定能否用全自动流程。

### 可以全自动（直接跑脚本）

- **头肩照 / 半身照**：人像下方有明确边界，`find_head_metrics()` 能正确定位头肩。
- **短发**（寸头、短发）：边缘短促整齐，抠图干净。

### 必须人工介入

| 情况 | 症状 | 处理 |
|---|---|---|
| **全身照** | 自动检测把"脚"当脖子，下巴偏 0.16，人高≈整图 | **手工标定**，见下方 |
| **长发 / 齐肩碎发** | 蓝底上头发外轮廓有蓝色描边 | 加严对比拉伸（见 references 第十四节）；**根治靠重拍扎发** |
| **发丝呈暖棕雾带** | 蓬散发外围一圈**暖棕**雾（R-B>20），放大才明显 | **不要调参**，见下方「暖棕发丝雾带」 |
| **背景有踢脚线/地板/阴影** | 四角采样被污染，去白边打折 | 手工指定背景色（取图中部两侧墙面） |
| **侧脸 / 低头 / 遮挡** | 抠图质量显著下降 | 重拍 |
| **深色短发+亮背景，发丛边缘发亮的灰** | 发丛上沿一圈灰，放大后明显 | **已解决**，`--transition-kill 60` 默认启用，见下方专节 |

### 深色短发 + 亮背景：发丛边缘"发亮的灰"（已解决，默认启用）

**症状**：黑短发的人，头顶发丛上沿有一圈**比蓝底亮的灰**。放大 5~6 倍看最明显，
像"发丝之间透出灰墙"。实测典型像素 `(149,140,137)`，比蓝底亮 48 个点。

**成因（关键，和暖棕雾带完全不同）**：

发丝与亮背景在原图里是**空间交替**（一根根碎发支棱着，缝隙透出墙），
边缘像素物理上就是"黑发丝 + 亮背景"的**空间混合**色，不是半透明叠加。

而 `compose` 的去污染公式 `true_fg = (fg - (1-a)*src_bg) / a` 假设的是
**alpha 混合**。对空间混合无效 —— 它只能算术反推出一个"中亮暖灰"第三色，
合成后比底色亮 48 个点，肉眼就是"发亮"。

**对策**：`--transition-kill`（默认 60）。过渡带内亮度 > 阈值的像素**直接判为背景**
（alpha→0），不做混合，消除第三色。

**阈值怎么定（实测，别凭感觉）**：

| `--transition-kill` | 发丛内灰像素 | 人像像素保留 |
|---|---|---|
| 0（关闭） | 832 | 100% |
| **60** | **611** | **98.7%** |
| 80 | 638 | 98.8% |
| 110 | 733 | 98.8% |
| 150 | 832 | 98.8% |

**收益在 ≤70 时饱和，60 留了余量。阈值调高反而变差**——
因为 `refine_alpha` 已先把过渡像素压暗，阈值设太高反而漏掉它们。

**⚠️ 两个坑（本会话踩过，别再走）**：

1. **`transition_kill` 和 `refine_alpha` 在做同一件事。**
   `refine_alpha` 已把 alpha 中间态从 4.20% 压到 2.06%。
   早期在不含 `refine_alpha` 的实验里测出"最优 110、收益 35%"，那是**假象**——
   走完整流程后收益只有 -27%，最优值也变成 60。**任何参数调优必须在完整流程里做。**

2. **必须在成品尺寸（缩放后）生效。** `compose` 现在在 `process` 里被
   排在 `resize` 之后调用，就是为此。

**性质说明**：这是**减淡不是消除**。原图那些像素里真的有背景色，只能三选一：
a) 判背景→变底色（发丝略缺，选它）b) 判前景→保留灰 c) 混合→发亮。
**根治靠拍摄端**：换深色背景拍，或拍照前把碎发抿平，让发丝与背景亮度差 ≤50。

### 暖棕发丝雾带（不是上面那种）：确实修不了，别试

**先分清两种"白边/灰边"**——成因完全不同，处理方式相反：

| | 颜色特征 | 成因 | 能不能修 |
|---|---|---|---|
| **深色短发灰边** | `(149,140,137)` 中性灰 R≈G≈B | 发丝与亮背景**空间混合** | **能**，`--transition-kill` 默认已处理 |
| **暖棕发丝雾带** | `(136,111,94)` 暖棕 R>G>B | 光穿透细发，发丝**半透明** | **不能**，见下 |

**判据：看 R 和 B 的差。** R-B > 20 是暖棕（修不了）；R≈B 是中性灰（已能处理）。

**暖棕雾带为什么修不了**：

| 目标 | 颜色 | 问题 |
|---|---|---|
| 要压暗的发丝 | `(136,111,94)` 暖棕 R>G>B | 宽度仅 2~4 px |
| 必须保护的皮肤 | 同为暖棕 R>G>B | — |

**两者颜色空间重叠，在 236×315 下无法线性分离。** 这是原片的光学事实，
u2net **如实抠出**，不是抠图错误。

已实测失败的四版判据：距离判据（`reach=22` 把脸染黑）、距离收窄（`reach=5`
够不着发丝）、中性色判据（圈到的全是背景过渡像素，一根真发丝都没圈到）、
以及本轮试过的所有后处理。

**必须修的话只有一条路：重拍**，让发丝不透光（逆光改顺光）。
**即使修好也不该修**：把发丝压成深色 → 蓬散发变实心黑块，比灰白更难看。

**正确回应用户**：说明根因是拍摄光线，建议**顺光重拍**（白天面向窗户，别背对窗户）。同时提醒——**236×315 实际尺寸下肉眼不可辨**，先用实际尺寸看再决定要不要重拍。

### 全身照的手工标定

逐行扫描 alpha 掩码宽度，找**脸最宽之后骤降 15% 以上**的那一行（下颌）：

```python
a = np.array(rgba)[:, :, 3]
for y in range(int(H*0.1), int(H*0.5), 10):
    r = np.where(a[y] > 128)[0]
    if len(r): print(y, y/H, r.max()-r.min())
```

实测：脸最宽 786px → 下颌 633px（降 18.5%）。头顶 = 第一个有人像的行。

然后调用 `build_crop_box()` 时传入手工的 `top`/`chin`/`cx`（可构造伪 metrics 字典）。

> ⚠️ **实测警告**：本节的"骤降 15%"判据**并非总是可靠**。妞妞照片上它把"脸最宽"定位到人高 27.9%（肉眼应为 22.8%），判出的下颌晚了 500+ px，裁切框直接跑到肩膀。
> **更稳的做法是读宽度曲线找"头部最宽平台 → 收窄 → 肩膀骤升"的三段结构**，用中间的收窄段定位下颌。必要时直接人工看图定 y。

### 长发照片的最优参数

```python
refine_alpha(rgba, src, src_bg,
             sim_sigma=60, sim_strength=0.90,
             lo_cut=0.20, hi_cut=0.80)   # lo_cut 从 0.05 提到 0.20
```

**切勿收缩 alpha 边界**——实测会让蓝晕从 1870 涨到 14797（暴露更多深色发丝边缘）。

### 分辨率底线

目标尺寸的 3 倍以上像素最稳妥（例：出 236×315，原图人脸区域最好 ≥700px 宽）。
